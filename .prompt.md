# Robot FTP Extension - AI Agent Prompt Guide

## Mission Statement
You are working on enhancing the **Robot FTP VS Code Extension** — a tool that enables Fanuc robot programmers to upload, download, and sync `.LS` files directly from VS Code using FTP, plus provides inline descriptions and code hints from CSV files.

## Context Before You Start
1. **This is a mature extension** (v0.3.5) with multiple releases
2. **Primary users**: Fanuc robot programmers in industrial settings
3. **Main language**: JavaScript (Node.js)
4. **Core dependency**: basic-ftp library for FTP operations
5. **IP-based connections**: Uses anonymous FTP to robot at configurable IP

## Critical Success Factors

### Must Always:
- ✅ Validate IP addresses using the existing regex pattern before connecting
- ✅ Reuse `getRobotIp()` function instead of creating new IP logic
- ✅ Close FTP client connections (`client.close()`) even if errors occur
- ✅ Set binary mode (`await client.send("TYPE I")`) before file transfers
- ✅ Use consistent error messaging: `vscode.window.showErrorMessage()`
- ✅ Log important operations to `outputChannel` for debugging
- ✅ Test path handling with `path.join()` for cross-platform compatibility

### Must Never:
- ❌ Hardcode IP addresses (except defaults in user prompts)
- ❌ Mix different error handling patterns
- ❌ Forget to handle the case where FTP connection fails
- ❌ Change the CSV format without major version bump
- ❌ Add features that require additional npm packages without documenting

## Code Patterns to Follow

### Pattern 1: FTP Operation Template
```javascript
async function performFtpOperation(destinationPath, fileType) {
  let ipAddress;
  try {
    ipAddress = await getRobotIp(destinationPath);
    vscode.window.showInformationMessage(`Using IP address: ${ipAddress}`);
  } catch (error) {
    vscode.window.showErrorMessage(error.message);
    return;
  }

  try {
    const client = new ftp.Client();
    client.ftp.verbose = true;
    await client.access({
      host: ipAddress,
      user: "anonymous",
      password: "anonymous",
      secure: false
    });

    // Your FTP logic here
    
    client.close();
    vscode.window.showInformationMessage("Operation completed successfully");
  } catch (error) {
    vscode.window.showErrorMessage(`Error: ${error.message}`);
  }
}
```

### Pattern 3: CSV Processing
```javascript
async function loadDescriptions(csvFilePath) {
  return new Promise((resolve, reject) => {
    const newDescriptions = {};
    
    if (!fs.existsSync(csvFilePath)) {
      // Handle missing file gracefully
      return resolve(newDescriptions);
    }

    fs.createReadStream(csvFilePath)
      .pipe(csv())
      .on('data', (row) => {
        if (row.Key && row.Description) {
          newDescriptions[row.Key.toLowerCase()] = row.Description;
        }
      })
      .on('end', () => resolve(newDescriptions))
      .on('error', (err) => reject(err));
  });
}
```

## Development Workflow

### When Adding a New Feature:
1. Create the function in `src/extension.js`
2. Register it in the `activate()` function
3. Add command entry to `package.json` under `contributes.commands`
4. Add context menu or keybinding if user-facing
5. Push to `context.subscriptions`
6. Update `README.md` with usage
7. Add entry to `CHANGELOG.md`
8. Test with actual `.LS` files if possible

### When Fixing a Bug:
1. Identify the function and root cause
2. Review similar functions for pattern consistency
3. Fix with minimal changes to avoid regression
4. Add error handling if missing
5. Update tests if applicable
6. Document in CHANGELOG.md as a patch

### When Refactoring Code:
1. Preserve the current API and command structure
2. Ensure all existing features still work
3. Maintain backwards compatibility with CSV format
4. Keep the same error message style
5. Don't change the package.json version (let maintainer do that)

## Testing Your Changes

Before committing:
1. Load extension in development mode (F5 in VS Code)
2. Test all modified commands manually
3. Check error messages are user-friendly
4. Verify no console errors in Output panel
5. Test on Windows (primary platform for industrial robots)
6. Review code for common mistakes above

## When Something Breaks

1. Check the error message first
2. Review recent changes to understand impact
3. Look at git diff to see what changed
4. Revert if uncertain, then fix incrementally
5. Add to CHANGELOG and communicate with users
